## 三、合成数据纪律

- 合成报告一律使用**假姓名白名单**（如 张三/李四/王五 或自造名单，登记于本文件附录）+ **假机构名**（如"示例体检中心A"，禁用任何真实机构名）。
- **植入真值**：合成生成器程序化标注——已知指标值 / 已知应标 H/L 哪些 / 已知趋势点（升/降/平稳）。真值与引擎共用同一处判定规则定义，禁止手写第二口径。
- 真值覆盖度门槛：按指标域与异常类型列最低覆盖项（自印区间覆盖默认值用例、无区间拒判用例、趋势点用例、低置信复核用例各不得缺位），写进基准 manifest（M1 建立）。

## 四、PII 纪律

- **真实体检报告永不入库、永不入 git、永不入示例目录**。
- PII gate + pre-commit hook 拦截（模式借鉴 bloodio）；台账 SQLite 文件（*.db）入 .gitignore。
- OCR 模型缓存目录不入 git。

## 五、数值口径纪律（一处定义）

以下规则只在 data/README.md 本节定义一次，plan/01 与代码注记一律引用本节，不得手写第二口径：

1. **区间三级优先**：① 报告自印区间（该行报告上印的区间，最优先）② 内置 WS/T 404/405 来源标注 YAML 常见项默认值（逐条标注分册与版本，注明"以报告单和医嘱为准"）③ 无区间 → 拒判：只展示趋势、不标异常。
2. **H/L 判定**：纯确定性边界比较——值 > 区间上限 = H；值 < 区间下限 = L；区间内 = 正常；无区间 = 拒判。边界值归属（闭/开区间）以内置 YAML 字段定义，随来源标注核对入库。
3. **趋势点**：同人对同 canonical_name 指标跨日期比较变化幅度，仅陈述事实幅度，不做解读。
4. **低置信阈值**：OCR 行置信度阈值以引擎配置文件单一字段定义（**落点：`src/checkup_ledger/data/config.yaml` 的 `ocr_threshold`**，随包分发、与知识库同属运行时必需数据），低于阈值强制人工复核，未复核不落库。**代码零默认值**：`ingest()` 入口无默认参数，缺字段/缺文件/非法值一律报错（不静默取字面值）。**实测**：降质扫描件每行分值均低于该阈值 → 未复核零落库。

## 六、M1 来源核对结论（2026-10-16）

**核对渠道**：工标网 csres.com 标准书目页（GBK 关键词检索，书目页可直连）。
**核对范围**：WS/T 404 系列各分册覆盖的检验项目、WS/T 405 的适用范围。

**结论一：M0 的 YAML 有三处分册号张冠李戴，已修正。**

| 条目 | M0 标注 | M1 核对后 | 依据 |
|---|---|---|---|
| ALT / AST | WS/T 404.1-2012 | ✅ 正确 | 404.1-2012 = 血清 ALT、AST、ALP、GGT |
| TC / TG / GLU | WS/T 404.1-2012 | ❌ → **未定位** | 404.1-2012 只覆盖上述四项酶，**不含脂类与血糖** |
| CREA | WS/T 404.5-2012 | ❌ → **WS/T 404.5-2015** | 404.5 现行版本为 2015（2012 版无此分册） |

**结论二：血脂、血糖、尿酸在 WS/T 404/405 系列中无对应分册。**
WS/T 404 系列是"临床常用生化检验项目参考区间"，分册覆盖酶类、蛋白、胆红素、电解质、
肾功能部分项（尿素/肌酐）、心肌酶、淀粉酶、CRP 等；脂类（TC/TG/HDL-C/LDL-C）、
血糖（GLU）、尿酸（UA）**不在其中**。故这三类的 `source.standard` 如实标
**"未定位（WS/T 404/405 系列无对应分册）"**，**不以方法标准（如 WS/T 412 血清甘油三酯
测定参考方法）冒充区间来源**——方法标准规定的是"怎么测"，不是"正常范围是多少"。

**结论三：WS/T 全文仍不可直连，区间数值无法核对 → 全部条目保持 `pending`。**
- `wsbz.org.cn` 域名无解析；`nhc.gov.cn` 返回 412；csres 全文付费。
- 故 `indicators.yaml` 的区间数值**一律未经原文核对**，`status` 全部为 `pending`。
- `pending` 按设计**不进判定路径**：报告未自印区间时走"拒判"（**宁拒判，不臆造**）。
- 各条目 `source.evidence` 已如实记录渠道与未核对状态。

**结论四：schema 已知局限（如实登记，不掩盖）。**
`canonical_name` 唯一 → 一个项目只能挂一份区间，性别/年龄分层的另一半（如女性 HGB 区间）
无处安放。当前处置：按"男性"如实标注 `applies_to.sex: male` 而**不写 any**（写 any 等于
把男性区间套给女性样本），分层区间的 schema 扩展留 M3，届时补对侧并加"不该命中"反向用例。

**M1 已建的样例与真值资产**（详见 `data/samples/manifest.json`）：

| 资产 | 位置 | 性质 |
|---|---|---|
| 合成报告（12 例） | `data/samples/cases/*.txt` | 字节冻结，程序化生成 |
| 植入真值 | `data/samples/truth/*.truth.json` | 只存"输入与期望"，**无观测字段** |
| 覆盖度门槛 + 逐 case 登记 | `data/samples/manifest.json` | 门槛以数据下发（非代码） |
| sha256 台账 | `data/ledger/assets.csv` | **生成物**，`tools/verify_ledger.py --update` 重算 |

**样例层如何模拟 `verified` 条目**（重要，防误读）：知识库条目一律 `pending`，
但样例层需要覆盖 `builtin_default` 来源形态。做法是把 YAML 区间当**夹具数据**
注入 `judge()` 的 `default` 参数——**不修改 YAML 的 status**，也不让 pending 进
真实判定路径。即：样例层验的是"引擎在收到已核对区间时的行为是否正确"，
不是"当前知识库已核对"。

## 七、M2 输入层夹具（2026-10-16）

模块① 输入层的合成夹具落在 `data/samples/ingest/`，与 M1 的样例集同属**开发期资产**
（不随包分发），但产物形态是**二进制**（PDF / PNG）——字节可复现的风险面与文本产物不同
（PDF 对象号、PNG zlib 压缩、字体渲染版本），故单设一套生成器与守门。

| 产物 | 形态 | 治什么 |
|---|---|---|
| `pdf/ingest-pdf-{plain,per-char,padded}.pdf` | 文本层可读 PDF（三种排版形态） | 伪空格、补白归一、跨行聚类 |
| `scan/ingest-scan-{clean,degraded}.png` | 笔画字体渲染的扫描件（一份清晰、一份确定性降质） | OCR 兜底、低置信复核闭环 |
| `truth/*.truth.json` | 只存"输入与期望行" | 端到端回归的期望值（**无观测字段**） |
| `manifest.json` | 用例登记 + 阈值来源 | 覆盖声明（**抽样覆盖非穷举**） |

**两条纪律（与 M1 同源）**：
1. **生成器确定性**：禁 stdlib `random` / 时钟 / `hash()`；落盘经原子写。
   渲染器自写（纯 `zlib`+`struct`），**不用 Pillow**——实测 Pillow 10.4 与 12.3
   渲染同一段文字 PNG 字节不同（抗锯齿随版本变），会让位级一致守门在升级时随机红。
2. **区间数值只在知识库一处定义**：夹具的行内容（含参考区间写法）全部从
   `indicators.yaml` 取；本生成器不写任何区间数值字面量。

**如实登记的局限**：自写笔画字体在 4×6 字形盒里，**次方符号（`^`）与波浪线区分度不足**
（OCR 读成 `~`/`>`）。故扫描件夹具**刻意避开含次方符号的单位写法**，覆盖同样多的路径
而读数可靠。这是**夹具渲染器局限，非 OCR 引擎缺陷**（真实字体下 `10^9/L` 读数正常）。

**阈值来源同源**：夹具 manifest 登记 `ocr_threshold_source` 指向随包 `config.yaml`，
低置信用例的判定阈值与运行期**同一处定义**（不在夹具里另写一份）。

## 八、M3 规范化层的口径落点（2026-10-16）

模块②（规范化层）把报告行映射成结构化记录。本节登记它引入的**新第三态**与
**两处口径决定**——口径仍以第五节为唯一源，本节只补"第五节没写到的第三态"。

### 1. 单位归一的三态（本节新增第三态，回写第五节第 4 条的同族纪律）

| 情形 | 原因码 | 处置 |
|---|---|---|
| 单位写了、且属于该指标量纲 | — | 归一到 canonical 单位（`IU/L`→`U/L` 等同量纲变体） |
| 单位写了、但认不出（或与该指标量纲不符） | `unit_unmapped` | 进待人工映射（**不回落成字典单位、不换算**） |
| **报告根本没写单位** | `unit_absent` | 进待人工映射 |

**"写了但认不出"与"根本没写"是两件事**：两者都要人工处理，但处置方向不同
（扩单位表 vs 核对报告排版）。故**拆成两个原因码**，不合并——合并会让留痕丢方向。

**"认得这个单位"不等于"它属于这个指标"**：单位表是全局的（`mmol/L` 被血脂与血糖共享）。
报告把 ALT 写成 `mmol/L` 时，全局匹配会拿血糖量纲的单位给肝酶的值背书——
**认得出但张冠李戴**，与"认不出"同属"不能照此判定"，同样进待人工映射。

**跨量纲换算首期不做**（口径见 `plan/04` 第四节）：认不出 → `unit_unmapped`，
**宁拒判不换算**（各指标换算系数是另一份口径）。

### 2. 自印区间的开闭语义（如实登记的口径决定）

报告只印**端点**（如"不超过某上限"），**不印开闭**。开闭是该指标的既定口径属性，
故自印区间的 `bounds` **沿用该指标在内置知识库条目里的口径**（`dictionary.bounds_for()`），
不在代码里硬编码某个标准的边界习惯。

**如实登记局限**：开闭**不是报告文本能表达的事实**——若某份报告实际用开区间而该指标
内置口径是闭区间，边界值的判定会与报告意图不符。首期接受这一局限（报告极少单独
标注开闭），登记于此以备后续扩展（如报告文本里出现"≤"/"<"前缀时按前缀覆盖）。

### 3. 无法映射的第三态（`pending_mapping`，不猜不丢）

原因码五态：`name_unmapped` / `unit_unmapped` / `unit_absent` / `value_unlocated` /
`range_unparsed`。共同纪律：**进"待人工映射"队列并留原文**，绝不静默丢弃、绝不猜。

**"印了区间但读不出" ≠ "报告没印区间"**（`range_unparsed` vs 未印占位符）：
把读错当"没印"，判定会从"有区间"变成"拒判"——一条真实的读错被伪装成一条干净的拒判
（用户看到"拒判"会以为报告没印区间，于是不去核对）。

### 4. 跨层对齐（模块侧 ↔ 样例侧同一口径）

`data/samples/truth/*.truth.json` 登记的 `canonical_name`/`value`/`unit`/`printed_range`
是"报告里写了什么"的**样例侧权威描述**；模块侧解析出的字段必须与它**逐条相等**
（`tests/test_normalize.py` 的 `test_sample_reports_normalize_to_truth_inputs`）。
两处若分叉（如一边归一变体、一边保留原文），样例层与模块层会各自"通过"而真实链路是错的。

## 九、M4 台账 / 导出 / 渲染的口径落点（2026-10-17）

模块④（台账）、⑤a（导出）、⑤b（渲染）把判定结果变成**可长期持有与可展示**的形态。
口径仍以第五节为唯一源，本节只登记这三层引入的**新决定**与**如实登记的局限**。

### 1. 台账只存事实，且唯一键是四列（缺一列都会静默丢数据）

台账表只有事实字段：`subject_id` / `canonical_name` / `date` / `value` / `unit` /
`flag` / `range_low` / `range_high` / `range_source` / `source_file` / `created_at`。
**无任何解读文本字段**（"建议/提示/结论"一类列一律不许有——由 `test_ledger.py` 的
列集断言 + `test_layering.py` 的"台账层不做判定"门守）。

唯一键 = `(subject_id, canonical_name, date, source_file)`，**四列缺一列都不行**：

| 漏掉的列 | 会静默发生什么 |
|---|---|
| `source_file` | 同一天两份报告的同名指标互相覆盖——不同机构印的区间不同，覆盖会丢掉"另一份说了什么" |
| `date` | 跨年同一文件名的记录被合并成一个趋势点 |
| `subject_id` | 家庭多成员的数据混在一起（扩展预留列失效） |

`source_file` 写入**不留 NULL**：SQLite 的唯一索引里 NULL 彼此不相等，留 NULL 会让
"重复 upsert"绕过唯一键、悄悄长出重复行。故来源未知时写**有值的空串**，并记注记
`source_file_absent` 说明有几条如此。

**日期形状必须逐段校验零填充**（`DATE_WIDTHS = (4, 2, 2)`）：`2024-3-11` 与
`2024-03-11` 字符串不等但语义相同，而唯一键按**字符串**比对——不校验就会让同一份
报告入库两次、折线上多出一个不存在的点。日历结构常数（一年几个月、一月最多几天）
是命名常量，**不是**区间端点，故零字面量门禁按真实 token 集比对时不会误报。

**`created_at` 一律为空串或显式传入值**：台账层不读系统时钟（读时钟会让"同输入双跑
逐字节一致"这一承诺在台账侧失效）。

### 2. 趋势三态由引擎一处实算，台账不重写"涨跌"口径

`series()` 读回序列后调 `engine.trend_delta` / `engine.trend_direction` 实算相邻变化——
与判定同源。首点无可比前值 → `delta`/`delta_pct`/`direction` 全为 `None`
（**不填 0**：0 是"没变化"这一事实，与"没有可比前值"是两件事）。
`delta_pct` 在前值为零时也为 `None`（除零不是"变化 0%"，是**无法表达**）。

**跨层对齐**：M1 真值在样例侧登记的 `expected_trends`（`from_value`/`to_value`/
`expected_delta`/`expected_direction`）与台账侧实算结果必须逐条相等
（`tests/test_ledger.py` 的 `test_ledger_series_matches_sample_truth_trends`）——
与第八节第 4 条的 K58 同族：两处若分叉，样例层与模块层会各自"通过"而真实链路是错的。

### 3. 导出只陈述事实：建议性词根是**出口常驻**断言

负向词表六个词根：`建议` / `可能` / `风险提示` / `注意` / `应` / `考虑`。
`export_summary` 每次写盘前跑 `assert_no_advisory_wording(artifact)`——命中即拒绝写出
（不是打印警告）。渲染层（`report/html.py`）**同样**过这道门：报告是给人看的那一份，
恰恰最容易写进"建议复查"这类话。

**产物末尾常驻免责段**，其措辞**刻意不含那六个词根**——否则"整份产物过词根门"与
"免责必须在位"两条会自相矛盾（"不做治疗建议"就会命中 `建议`）。

**缺值与"零"必须可区分**：没有既往可比值 → 变化列**留空**；持平 → `0` 与 `0%`。
产物里的标记与来源用 canonical token（`high`/`report_printed`），不换人话标签——
CSV 与 Markdown 两处各维护一套标签，早晚一处改了一处没改。人话标签只在渲染层出现。

**同一天的历史不算可比前值**（`_latest_before` 只取**严格早于**当前日期的最近一条）：
否则同一天重跑导出的两份摘要互相成为"上次值"，变化幅度会变成 0——那会把"这次没变"
这个假事实写进产物。

### 4. 渲染零判定：算术与比较只准落在 `chart.py`（如实登记的分界口径）

画折线**必须**做算术（坐标换算）与比较（求值域上下界）——把这两件事挤进装配模块，
就只能靠"别再写比较"这句口头纪律守，而它守不住。故按**语义**划线：

| 模块 | 允许 | 禁止 |
|---|---|---|
| `report/chart.py`（图元计算） | 算术、比较（求域上下界）、分位统计 | 判定态常量（`FLAG_*`）、import 判定内核、文件 I/O、时钟 |
| `report/html.py` / `report/trend.py`（装配） | 拼接、格式化、取空值 | 算术（除字符串拼接）、大小比较、import 判定内核 |

**分界线是语义而非"有没有运算符"**：求域上下界是数值之间的比较（图元本职），
"这个值是否越界"是判定（模块③ 的本职）——前者留在 `chart.py`，后者一律不许出现。

**"无历史可比" ≠ "分位 0%/100%"**：单点序列的"分位 = 100%"算术上成立，但会让人
读成"处在历史最高位"——而那次根本没有历史可比。故观测数 < 2 → `None`
（与"拒判 ≠ 正常"同族：没有可比对象时如实说没有，不给出一个看起来有信息量的数字）。

**无区间（拒判）→ 不画区间带**：如实留白，**不补一条"看起来正常"的带**。
带的位置由区间端点撑开值域保证（值域必须含端点，否则带会被裁到画布外）。

### 5. 首启免责与台账库的落点（用户主目录，不是仓库）

- 免责标记落 `~/.checkup_ledger/accepted`；台账库缺省落 `~/.checkup_ledger/ledger.db`。
  **为什么不落仓库**：台账是个人健康数据，落仓库会让 `git status` 就看得见——
  PII gate 只在提交时拦，那时文件已经在工作树里了。
- 标记文件**只记"接受过"这一个事实**（不写时间戳/机器名——一个免责标记不该变成指纹）。
- **写不进去不算失败**：只读/受限环境下免责照样打印，只是每次再念一遍。
  （`mark_accepted` 须同时接 `OSError` 与 `ValueError`：路径含非法字符时
  `os.makedirs` 抛的是 `ValueError`。）
- `*.db` 已在 `.gitignore`；PII gate 的类型面拦 `*.db`/`*.sqlite`——
  `tests/test_pii_gate.py` 新增三条（真建台账库被拦 + `.gitignore` 覆盖 + 仓库无被跟踪 db）。

## 十、M5 冻结交付面的口径落点（2026-10-17）

### 1. 随包数据白名单**单一来源** = `pyproject.toml` 的 `package-data`

`data/*.yaml|yml`（包内 `src/checkup_ledger/data/`）+ `benchmark/*.json`。冻结构建脚本
**从它实算展开**、再派生落点，不手写第二份清单。落点两条（对应两个运行时消费者）：

| 白名单 | 落点 | 谁在读 |
|---|---|---|
| `data/*.yaml` | exe 旁 `data/` | `paths.resolve_data_dir()` 冻结态分支读 `<frozen_root>/data` |
| `benchmark/*.json` | 包内 `checkup_ledger/benchmark/` | `benchmark.runner.cases_path()` 按模块 `__file__` 定位 |

**`data/*.yml` 是声明为空模式**：仓库当前只有 `.yaml`（19 条知识库条目），保留 `.yml`
模式是为将来新增 `.yml` 分册时不必改安装面声明。这类"合法的空模式"**逐条登记理由**
（`freeze_build.DECLARED_EMPTY_PATTERNS`，由测试锁死清单）；未登记的空模式仍然报错。

### 2. 样例集**不随包**（开发期资产 ≠ 运行时必需）

`data/samples/` 按 `plan/04` 第一节属 **B 类合成样例集**——它是**开发期资产**（基准的
样例驱动层、生成器的产物），不进安装面也不进冻结构建命令；`test_frozen.py` 专条断言
"构建命令不拷样例集 + 白名单实算结果不含样例集"。冻结产物内 `bench` 的样例层如实报
"未启用（样例集不在位）"，只有规则驱动层跑（不伪造通过）。

### 3. "零上传"的口径边界（**实测偏差，如实登记**）

可扫断言的口径是**"无可出站能力的组件"**：TLS（`ssl`/`_ssl`/`libssl`）、HTTP
（`http`/`urllib.request`）、FTP/SMTP/telnet/XML-RPC、异步与并发调度——一律不在包内。

**但 `socket` 这个名字排不掉**：`pdfminer/__init__.py` 在模块级
`from importlib.metadata import version` → `importlib.metadata` 模块级 `import email`
→ `email.utils` 模块级 `import socket`；强行 `--exclude-module socket` 会让
`import pdfplumber` 直接 `ModuleNotFoundError`（实测 `ingest` 报 exit 3）。
故保留 `socket`/`selectors` 这两个**不含协议栈**的名字并**显式登记**
（清单 + 理由 + 测试锁死 + 变异验证）。**判据 = 有没有出站能力，不是有没有那个字符串**——
这条边界写在这里，免得后来者把它读成"零上传已放松"。

### 4. 打包确定性的口径边界

- **成立**：同一份 dist 两次打 zip **逐字节一致**（`ZIP_STORED` + 条目排序 + 固定
  `date_time`/`create_system`/`external_attr`）。
- **不成立**：exe 本体**逐字节可复现**——实测同机连打两次的 exe sha256 都不同
  （体积相同、构建期时间戳不同）。故留档口径是"打包过程确定"，不是"产物可复现"。

### 5. 内嵌数据对账的判据（**双向**，不是只查漏拷）

① 白名单每条都在产物里（查漏拷）→ ② 产物两个数据目录里的文件都在白名单内（查多拷）
→ ③ 逐份 sha256 与仓库冻结件一致（防构建期被改写/归一化）。只做 ① 的门对"顺手把样例集
也打进去"是瞎的——那正是"包内容与承诺不符"的另一半。

### 6. 免责标记的落点边界：**解不出主目录就不写**（M5 实测收窄）

第九节第 5 条定的落点是"用户主目录"（`~/.checkup_ledger/accepted`）。M5 在中立环境
（`env -i` 等价）跑冻结产物时发现：环境里没有 `USERPROFILE`/`HOMEDRIVE`+`HOMEPATH`/
`HOME` 时，`os.path.expanduser("~")` **原样返回字符串 `~`**，经 `abspath` 就变成
"**当前工作目录下的 `~` 文件夹**"——实测跑 `ledger`（触发首启免责）后，工作目录里
真的多出 `~/.checkup_ledger/accepted`。

这与"纯本地、不写用户没让写的地方"的承诺相冲突，故口径收窄为：
**解不出主目录 = 没有可写的标记位置 → 不写**（返回 `False`、不抛错、**绝不回落 CWD**），
按"未接受"处理（免责照念，宁可多念一次）。用户主目录**可解析**时行为不变。
