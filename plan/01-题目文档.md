> - **定位宣言**："三年前那项指标是多少来着？"——把历年体检报告（PDF/扫描件）录入成个人检验指标台账，做纵向趋势曲线+按参考区间的异常标记+就诊摘要导出。**纯本地零上传、数据整理 not 医学**：数值判定 100% 交给确定性代码（H/L/趋势），区间三级优先（报告自印区间 > 内置标注来源的常见项默认值 > 拒判），不做解读不做分诊。

## 一、介绍

**痛点**：体检报告一年一份，散落在微信/邮箱/纸质抽屉里。"三年前那项指标是多少来着？""这两年是升是降？"——个人没有任何趁手的纵向数据整理工具。体检机构报告格式各异，PDF/拍照混存；检验数值旁边的参考区间每家医院、每台仪器都可能不同，跨年对比时"哪次是异常"本身就说不清。

**开源空白（基准日 2026-10-15，gh api 检索）**：

- 国外强势项目走的是 **AI 解读路线**：OpenHealthForAll/open-health（3961★，LLM 健康助手，非确定性历史对比，中文版式非重点）；ashugaev/bloodboy-biomarkers-tracker（23★）；机构级 LIS（senaite.core 396★ / OpenELIS）面向机构而非个人。
- 中文最直接相关的是 Hubert-hwk/Health-Flow（141★，中文体检报告解析+生化趋势），但其技术路线是 **VLM+Agent+智能分诊**——与本题**必须切割**：本题是确定性代码判定（vs 它的大模型）、纯本地零上传（vs 它的云端）、不做分诊。
- 其余 blood-test-parser / bloodio / CareTrace / Washyu0826 / health-report-reader 等均为 0-6★ 原型。
- **判定**："中文 + 纯本地零上传 + 历史纵向对比 + 确定性异常标记"四要素组合接近空白（软论据⬜，检索式记入 data/README.md）。

**关键设计（区间底座的双先例验证）**：

- WS/T 404/405 系列卫生行业标准全文**不可直连**（卫健委 wsbz 平台 412/502 反爬，工标网 csres.com 仅书目、全文付费）⬜。
- **降级方案是该细分最佳实践（不是妥协）**：先例① LabLens（yang-rz-602/lablens，0★）手工整理 95 项中文参考区间入 YAML（indicators_biochem.yaml 等，来源标注 WS/T 404.1/404.2/404.3-2012 分册），核心设计"报告单印的区间 > 知识库 > 拒判"三级优先，并引用 Meyer 等（Frontiers in AI 2025, DOI 10.3389/frai.2025.1681979，LLM 自报区间 CV 26.5%）与 Lab-AI（arXiv:2409.18986，GPT-4 无检索区间准确率 42.9%）论证"各医院仪器试剂不同，**报告上印的才是有效区间**"；先例② bloodio（simones99/bloodio，0★）local-first 浏览器解析，明示 "compares values with the **reference ranges printed on the report**"。
- → 本题区间层设计：**报告自印区间（最优先） > 内置 WS/T 404/405 来源标注 YAML 常见项默认值 > 无区间只展示趋势不标异常（拒判）**。

**输入格式现实**：体检机构电子 PDF 通常文本层可复制，但个人留存常为拍照/扫描图 → **OCR 首期必需**：RapidOCR（RapidAI/RapidOCR，8148★，ONNX Runtime CPU 本地推理，中文印刷表格主力场景）✅；低置信行强制人工复核（bloodio confidence/review 机制先例）。

## 二、任务要求

首期 **5 个模块**，其余留扩展。每模块必须写明 输入/输出/确定性纪律（**"未挂来源核对不得落库/生效"**）。

### 模块①：输入层（PDF/扫描件导入）

- **输入**：体检报告 PDF（文本层可直读）或拍照/扫描图片。
- **输出**：结构化行级草稿（原始行文本 + 页码 + 行置信度）。
- **引擎**：PDF 优先走文本层直读（pdfplumber/PyMuPDF 类）；扫描件兜底走 **RapidOCR 本地推理**（ONNX Runtime CPU，零联网）。
- **确定性纪律**：OCR 低置信行**强制人工复核**，未经复核确认的行不得进入规范化层；复核界面/流程须留存"原始行—人工确认值"对应记录。

### 模块②：指标规范化层（指标名字典）

- **输入**：行级草稿中的指标名原文（如"谷丙转氨酶/ALT/丙氨酸氨基转移酶"等异名）。
- **输出**：canonical_name + aliases + 单位归一后的结构化记录；无法映射的进"待人工映射"队列。
- **引擎**：指标名字典 YAML（schema 借鉴 lablens 模式：canonical_name / aliases / unit / 所属分册来源标注）。
- **确定性纪律**：字典每一条目必须挂来源核对（报告实测词 + 来源标注）；**未挂来源核对的条目不得生效**；单位归一规则一处定义（data/README.md 数值口径纪律节）。

### 模块③：区间层（三级优先判定）

- **输入**：结构化记录 + 该行报告自印参考区间（如有）。
- **输出**：H/L/正常/拒判 四态标记 + 所用区间及其来源（报告自印 / 内置默认 / 无区间）。
- **引擎**：三级优先——**① 报告自印区间（最优先）② 内置 WS/T 404/405 来源标注 YAML 常见项默认值 ③ 无区间 → 只展示趋势不标异常（拒判）**。H/L 判定为纯确定性比较（值 vs 区间边界），一处定义（data/README.md）。
- **确定性纪律**：内置默认值每条必须标注来源分册与版本；无来源标注的默认值不得进入判定路径；判定代码不做任何"解读"输出。

### 模块④：纵向台账与可视化

- **输入**：已判定记录。
- **输出**：本地 SQLite 台账（按人/指标/日期）；单指标时间序列折线 + 自身历史分位 + 参考区间带状背景。
- **引擎**：SQLite（本地文件，入 .gitignore）+ 折线图（本地渲染，CLI 形态可产本地 HTML）。
- **确定性纪律**：台账只存事实数值与判定标记；真实报告文件与台账 db **永不入 git**（PII gate + git hook，模式借鉴 bloodio）。

### 模块⑤：导出与真值基准

- **输出A（就诊摘要导出）**：CSV/Markdown，只陈述事实数值与变化幅度（"X 指标由 A 升至 B，变化 +C%"），不含任何建议性语句。
- **输出B（真值基准）**：合成报告样例集 + 植入真值——已知指标值 / 已知应标 H/L 哪些 / 已知趋势点，程序化标注，作为回归基准。
- **确定性纪律**：合成数据纪律见 data/README.md（假姓名白名单+假机构名）；导出文案逐字校验无建议性词根（"建议/可能/风险提示"等不得出现在导出物）。

**扩展项（首期不做）**：多语言 OCR；更多内置区间分册；家庭多成员管理。

## 六、边界与非目标

- **不是医疗器械**：不做诊断、不做解读、不做分诊、不做治疗建议。数值判定仅为 H/L/趋势的机械比较。
- **免责红线**：首启免责声明（借鉴 bloodio "not a medical device...does not interpret, diagnose or suggest treatment. A disclaimer is shown on first launch" 与 CareTrace "not a doctor and does not replace a doctor" 原文范式）+ README 常驻免责；lablens 数据文件注释范式："本字典仅用于检验结果的机械判定（H/L/危急），不构成诊断依据。各医疗机构应以本机构 LIS 打印区间为最终准绳。"
- **区间默认值纪律**：内置区间默认值必须逐条标注来源分册与版本，并注明"以报告单和医嘱为准"。
- **隐私红线**：健康数据极敏感——纯本地、零上传、零遥测；**真实报告永不入 git、永不入示例目录**（PII gate + pre-commit hook 拦截，模式借鉴 bloodio）。
- **品牌隔离**：本题是**个人健康数据管道**（C端个人、纵向数据整理），与同系列既有题材（方向级描述：合规审计类，**具体领域按品牌隔离纪律不展开**）完全脱钩：命名避开医疗审计词系（避开"诊断/解读/分析/AI助手"词根，用"台账/工作台"词系）、判定逻辑完全独立、文档不提及任何姊妹项目。
- **首期范围限定**：仅上述 5 模块；多语言 OCR、更多内置区间、家庭多成员管理等一律留扩展项，防 scope 失控。
- **结论纪律**：导出物与界面文案只陈述事实数值与变化幅度；无出处的数值不用确定语气。
