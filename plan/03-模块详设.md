## 通用约定（全模块生效）

**确定性纪律的通用表述**：**"未挂来源核对不得落库/生效"**——凡是要进判定路径或台账的东西，必须能指认它的来源；指认不了就进"待人工处理队列"并显式可见，**不猜、不编、不静默取默认值**。

**四种状态用词统一**（避免各模块自造词汇）：

| 词 | 含义 | 禁止混用为 |
|---|---|---|
| `pending` | 待人工处理（未复核 / 未映射 / 来源未核对） | 不等于失败，也不等于通过 |
| `not_assessed` | 拒判：无可用区间，只展示趋势 | 不等于"正常" |
| `skipped` | 不适用（原文/设计明确写了例外情形） | 不等于"没做" |
| `unknown` | 未观测到（"没看到"而非"缺失"） | 不等于"没有" |

**"拒判"与"没做"必须可区分**：`not_assessed`（无区间，我不判）与"程序没跑到这里"在产物里是两种记录；凡是"没查"的地方**单列一节**，绝不混进判定三态（防"没查"被读成"查了没问题"）。

## 模块① 输入层（ingest）

### 职责
把 PDF / 扫描图变成**行级草稿**：原始行文本 + 页码 + 行置信度。**只做抽取，不做任何数值语义判断。**

### 接口

```python
def ingest_pdf_text_layer(path: Path) -> list[RawLine]      # 文本层直读（依赖 [pdf]）
def ingest_images(paths: list[Path]) -> list[RawLine]        # OCR 兜底（依赖 [ocr]）
def ingest(path: Path, *, ocr_threshold: float) -> IngestResult
```

`IngestResult`：`lines: list[RawLine]` / `engine: str`（`pdf_text` / `ocr`）/ `pending_review: list[RawLine]`（低置信行）/ `notes: list[Note]`。

### 确定性纪律
- **低置信行强制人工复核**：`confidence < ocr_threshold` → 进 `pending_review`，**未经复核确认的行不得进入规范化层**。
- 复核留痕：`reviewed` 记录"**原始行 → 人工确认值**"的对应关系（`ReviewRecord`：`line_ref` / `original_text` / `confirmed_text` / `reviewer_note`），可审计。
- **阈值单点定义**：`ocr_threshold` 出自配置文件单一字段（`data/README.md` 口径节第 4 条），**代码零默认值**——缺配置即报错，不静默取 0.8 之类的字面值。
- **缺依赖走契约**：未装 `[pdf]`/`[ocr]` 时 `exit 3`（不裸抛 `ImportError`），且 `try/except ImportError` 包住**从 import 到调用完成**的整条路径（不是只包 import 行）。

### 必防的工程陷阱（sprint 实录同族）
- 字符逐个定位的伪空格（PDF 导出常见）→ 行内多空格归一后再抽取；
- 多行数值/区间跨行时**按 y/x 邻近聚类合并**再解析；
- CRLF 残留与中文路径；GBK 控制台编码（入口守卫兜）。

### 实现注记（M2 落地，含实测修正）

**① 不用 `pdfplumber.extract_text()`**：实测逐字定位导出的 PDF 上，原生文本抽取会把
`U/L` 拆成 `U/ L`（它按字符间距猜空格，而逐字定位的字距没有真实空白字符可依）。
故本模块**取字符坐标自行装配**：优先认**真实空白字符**；整行无空白字符时按
"间隙 > 0.75 × 行内字符均宽"判空格（基准从该行碎片**实算**，不写死像素常数）。
三种形态（正常/逐字定位/补白）经装配后得到**逐字相同**的行。

**② 空格判定基准必须是"字符均宽"而非"相邻间距"**：首版用后者，在两三个碎片的行上
退化成"间距 = 它自己"，阈值被抬到判不出空格（`U/L` 粘成 `U/L`）；也试过"间隙排序找
跳变"，会落在字形抖动的量级上，把 `ALT` 拆成 `A L T`。均宽基准不受个别抖动支配。

**③ 缺依赖守卫必须包住"从 import 到调用完成"**：只包 import 行是**假门**——
pdfplumber 在 `open()` 内部才 import pdfminer，RapidOCR 在**构造引擎**时才 import
onnxruntime。故 `deps.run_guarded()` 把整个可调用对象包进 `try/except ImportError`，
并由 `test_guard_covers_call_time_import_not_just_import_line` 用"顶层可导入但
`open()` 抛 ImportError"的形态守住这条防线。

**④ OCR 引擎可注入**（`engine_factory`）：回归测试用**确定性桩引擎**
（`make_scripted_engine`），这样"低置信 → 待复核 → 复核放行"的闭环在**没有 OCR 权重**的
环境里也能真跑；也让"低置信行"可精确构造，不必靠把图故意糊掉碰运气（那在 CI 上会随机红）。

**⑤ 阈值单点定义**：`ocr_threshold` 来自随包 `data/config.yaml`，`ingest()` 入口
**无默认参数值**（有默认值 = 代码里又定义了一次阈值）。缺文件/缺字段/类型非法/越界
一律抛 `ConfigError`（CLI → exit 1，属配置缺陷而非用法错误）。

### 测试点
| 用例 | 断言 |
|---|---|
| 文本层样例 | 行数 = 真值行数；每行 `page`/`text` 正确 |
| 低置信合成样例 | 低于阈值的行**全部**进 `pending_review`，零漏 |
| 未复核门禁 | 未复核行**不出现在**规范化层输入（阴性对照：复核后出现） |
| 缺依赖 | 打桩 `builtins.__import__` 令 `pdfplumber` 抛 `ModuleNotFoundError` → `exit 3`，不裸异常 |
| 双跑字节一致 | 同输入解析两次，序列化 JSON 逐字节相等 |

## 模块② 规范化层（normalize）

### 职责
指标名原文 → `canonical_name`；单位归一；**无法映射的进"待人工映射"队列**。

### 接口

```python
def normalize(lines: list[RawLine], *, dictionary: MeasurementDictionary) -> NormalizeResult
def normalize_ingest(result: IngestResult, *, dictionary: MeasurementDictionary) -> NormalizeResult
def normalize_document(lines, *, knowledge_path=None) -> NormalizeResult   # 编排：唯一读文件处
```

`NormalizeResult`：`measurements: list[Measurement]` / `pending_mapping: list[PendingMap]`（原文 + 原因码）/ `notes: list[Note]`。
`PendingMap`（IR 新增）：`line_ref` / `raw_text` / `reason` / `raw_name` / `raw_unit`。
原因码五态：`name_unmapped` / `unit_unmapped` / `unit_absent` / `value_unlocated` / `range_unparsed`。

`normalize` 是**纯函数**（别名/单位表经参数接收，不读文件）；`normalize_ingest` 是
**唯一接续点**（只吃模块① 放行的行，且挡"复核门被绕过"）；`normalize_document` 加载
知识库后调用 `normalize`——**模块② 唯一读文件处**（与模块① 的 `ingest` 同形态）。

### 指标名字典 schema（YAML，借鉴 lablens 模式）

```yaml
# src/checkup_ledger/data/indicators.yaml
schema_version: 1
indicators:
  - canonical_name: ALT
    display_name: 丙氨酸氨基转移酶
    aliases: [谷丙转氨酶, ALT, 丙氨酸氨基转移酶, GPT]   # 报告实测词逐一登记
    unit: U/L
    unit_aliases: [U/L, IU/L, u/l]
    source:
      standard: WS/T 404.1-2012        # 来源分册
      status: pending                  # pending | verified
      note: 常见项；以报告单和医嘱为准
```

### 确定性纪律
- **字典每一条目必须挂来源核对**（报告实测词 + 来源标注）；**未挂来源核对的条目不得生效**——loader 入口硬门：`source.standard` 或 `source.status` 缺失 → **拒绝加载**并在"未启用清单"显式列出原因。
- `status: pending` 的条目**不进判定路径**（可用作别名匹配展示，但不得作为区间默认值来源）。
- **单位按最长优先匹配**（否则 `2mg` 被短单位 `g` 吃成 2 克，值静默放大一千倍）；**认不出的单位 → `pending` + 原因码 `unit_unmapped`**，不落 `not_found`（"写了但单位不认识"与"根本没写"是两件事）。
- **别名表不另建第二份**：别名只在 YAML 一处定义，解析层经参数接收（保持纯函数不读文件）。
- 无法映射 → `pending_mapping`（原文 + 原因码），**不猜、不静默丢弃**。

### 测试点
| 用例 | 断言 |
|---|---|
| 异名映射 | `谷丙转氨酶`/`ALT`/`GPT` 均映射到同一 `canonical_name` |
| 未挂来源不生效 | 构造一条缺 `source.status` 的条目 → loader **拒绝加载** + 未启用清单列原因（变异验证：补上 status 后变绿） |
| 单位最长优先 | `2mg` 解析为 2 毫克（**不是** 2 克）；`2mg` vs `2m` 边界 |
| 单位未识别 | `net: 2oz` → `pending(unit_unmapped)`，**不是** `not_found` |
| 未映射不猜 | 故意写错指标名 → 进 `pending_mapping`，不进 `measurements` |

### 实现注记（M3 落地，含实测修正）

**① 拆成"纯函数件 + 编排层"三件**（`mapping.py` / `parse.py` / `pipeline.py`）：
别名表与单位表**经参数接收**，故 `mapping`/`parse` 可以完全不碰文件系统。
这不是洁癖——它让"别名表只在 YAML 一处定义"这条纪律有**可注入的验证通道**：
测试与基准可以塞一个夹具字典，而不必去改真实知识库（改了知识库就动了台账 sha256）。
文件读取唯一落在 `pipeline.py`，由静态门禁守（`test_normalize_layer_only_pipeline_reads_files`）。

**② 单位"最长优先"是前缀匹配 + 取最长，不是"包含匹配"**：包含式匹配会在
`mg` 里找到 `g`，把"毫克"读成"克"——**值静默放大一千倍且毫无提示**。故规则是
"原文以某别名**开头**"的别名集合里取最长者（同前缀家族 `m`/`mg`/`mmol/L` 由此正确分开）。

**③ 单位还须"属于该指标"**（M3 实测补的一道门）：单位表是**全局**的（`mmol/L` 被
血脂与血糖共享），故"认得这个单位"不等于"它属于这个指标"。报告把 ALT 写成 `mmol/L`
时若只做全局匹配，会拿血糖量纲的单位给肝酶的值背书——**认得出但张冠李戴**，
与"认不出"同属"不能照此判定"，同样进待人工映射（不换算、不猜）。

**④ 区间列的"没印"与"读不出"必须分开**：`（未印）` → `printed=None`（报告声明没印）；
`<下限>~<非数字>` → `range_unparsed`（进待人工映射）。把后者当"没印"，判定会从
"有区间"变成"拒判"——**一条真实的读错被伪装成一条干净的拒判**（用户看到"拒判"会
以为报告没印区间，于是不去核对）。故区间一侧的分类是三态（不设限 / 数值 / 读不出）。

**⑤ 原因码按"处置方向"细分**（M3 实测修正）：首版把"没写单位"与"认不出单位"合并成
一个码。两者都要人工处理，但**处置方向不同**（核对报告排版 vs 扩单位表），故拆成
`unit_absent` 与 `unit_unmapped`。同理"数值+单位粘住"（`<数值><单位>`）的写法必须
先拆开——否则整段解析失败会误报成 `value_unlocated`，人工按"数值没读到"去找就错了方向。

**⑥ 自印区间的开闭语义取自知识库条目**：报告只印端点、**不印开闭**，而开闭是该指标的
既定口径。故 `_printed_range` 用 `dictionary.bounds_for()` 赋 bounds——否则"不超过上限"
这类区间的边界值会被判反。**局限如实登记**：开闭是口径属性、不是报告文本能表达的事实，
故自印区间的开闭**沿用该指标的内置口径**（见 `data/README.md` 第八节）。

**⑦ 编排层的"防绕过"检查**：`normalize_ingest()` 在接续模块① 产出时，若发现同一行
**既在 `lines` 又在 `pending_review`**（上游复核门被绕过），**报错**而不是照常处理。
只靠"上游保证"是弱保证——纪律需要在**唯一接续点**上有可执行的守卫。

## 模块③ 区间判定层（judge）—— 承重件

### 职责
结构化记录 + 该行**报告自印区间** → H / L / 正常 / 拒判 四态标记 + 所用区间及其来源。

### 接口

```python
def judge(m: Measurement, *, defaults: IndicatorDict) -> Judged     # 纯函数，无 I/O
def judge_all(ms: list[Measurement], *, defaults: IndicatorDict) -> list[Judged]
```

### 三级优先（口径唯一源 = `data/README.md` 第五节第 1 条）

| 优先级 | 来源 | `range_source` |
|---|---|---|
| ① 最优先 | **报告自印区间**（该行报告上印的） | `report_printed` |
| ② 其次 | 内置来源标注 YAML 常见项默认值（`status: verified` 才可选） | `builtin_default` |
| ③ 兜底 | 无区间 → **拒判**：只展示趋势、不标异常 | `none` |

### 边界语义（口径节第 2 条）
- `值 > 上限` → `high`；`值 < 下限` → `low`；区间内 → `normal`；无区间 → `not_assessed`。
- **边界值归属（闭/开）以内置 YAML 字段定义**（`bounds: closed` 默认 / `open`），随来源标注核对入库——禁止在代码里硬编码某个标准的分册边界习惯。

### 确定性纪律
- 判定为**纯确定性边界比较**，**纯函数、无 I/O、无随机、不读时钟**。
- **不做任何"解读"输出**：不产生"注意""建议""可能""风险"等字样（导出物逐字校验词根，见模块⑤）。
- **内置默认值每条必须标注来源分册与版本**；无来源标注的默认值**不得进入判定路径**。
- **区间数值只在 YAML 一处定义**（零字面量门禁守 M1 建立）。

### 测试点（含边界双向）
| 用例 | 断言 |
|---|---|
| 三级优先 | 自印区间与内置默认不同 → 判定用**自印**（`range_source=report_printed`）；真值基准含"自印覆盖默认值"用例 |
| `threshold_exact` | 值恰等于边界（如"不超过 40"的 40）→ 按 `bounds` 语义判 normal（闭）/ high（开） |
| `near_miss` | 差一点不到边界 → **不命中**（防阈值语义从未被测） |
| 拒判 | 无自印区间 + 无 verified 默认值 → `not_assessed` + `range_source=none`（**不是** `normal`） |
| pending 默认值不进路径 | `status: pending` 的默认值 → 拒判（变异验证：改 verified 后参与判定） |
| 反向样例 | 一条**不该命中**的区间判定用例（防适用域写错永远不红） |
| 双跑一致 | 同输入判定两次，结果与序列化逐字节一致 |

## 模块④ 纵向台账与可视化（ledger / report）

### 职责
已判定记录 → 本地 SQLite 台账（按人/指标/日期）+ 单指标时间序列折线 + 自身历史分位 + 参考区间带状背景。

### 接口

```python
def open_ledger(path: Path) -> Ledger                       # 建表/迁移
def upsert(ledger: Ledger, judged: list[Judged], *, subject: str, date: str) -> int
def series(ledger: Ledger, canonical_name: str, *, subject: str) -> list[TrendPoint]
def render_html(ledger: Ledger, *, out: Path, subject: str) -> Path      # M4
```

### 台账 schema（M0 定稿，`subject_id` 为家庭多成员扩展预留）

```sql
CREATE TABLE measurement (
  id INTEGER PRIMARY KEY,
  subject_id TEXT NOT NULL DEFAULT 'default',   -- 扩展预留
  canonical_name TEXT NOT NULL,
  date TEXT NOT NULL,                            -- ISO 8601，显式传入
  value REAL NOT NULL,
  unit TEXT NOT NULL,
  flag TEXT NOT NULL,                            -- high|low|normal|not_assessed
  range_low REAL, range_high REAL,
  range_source TEXT NOT NULL,                    -- report_printed|builtin_default|none
  source_file TEXT,
  created_at TEXT                                -- 仅本机元信息，不入导出物
);
CREATE UNIQUE INDEX ux_measure ON measurement(subject_id, canonical_name, date, source_file);
```

### 确定性纪律
- 台账**只存事实数值与判定标记**，不存任何解读文本。
- **真实报告文件与台账 db 永不入 git**（PII gate + pre-commit hook，模块①的复核留痕同理）。
- **渲染层零判定**：`render_html` 只消费既有 `Judged`，**不重算任何比较**（AST 断言：渲染模块内无 `BinOp` 比较运算、无区间数值字面量）。
- **零外链硬断言**：渲染出口常驻 `assert_no_external_resources(html)`——断网可开，不是"测试里验一次"。

### 测试点
| 用例 | 断言 |
|---|---|
| 台账往返 | upsert 后 series 读回，数值与 flag 逐条一致 |
| 唯一键 | 同一 (人, 指标, 日期, 文件) 重复 upsert 不产生重复行 |
| 趋势点 | 跨日期比较变化幅度正确（升/降/平稳三形态各一例） |
| 渲染零判定 | AST：渲染模块无区间比较、无阈值字面量（变异验证：塞一个比较进去必红） |
| 零外链 | 产物 HTML 无 `http://`/`https://`/`//cdn` 等外链；`assert_no_external_resources` 常驻 |
| db 不入 git | .gitignore 覆盖 + PII gate 拦截 `*.db` |

## 模块⑤ 导出与真值基准（export / bench）

### 输出A：就诊摘要导出
CSV / Markdown，**只陈述事实数值与变化幅度**（"ALT 由 32 升至 47，变化 +46.9%"），**不含任何建议性语句**。

### 输出B：真值基准
合成报告样例集 + 植入真值——已知指标值 / 已知应标 H/L 哪些 / 已知趋势点，程序化标注。

### 接口

```python
def export_summary(judged: list[Judged], *, fmt: str, out: Path) -> Path     # csv | md
def run_bench(cases: Path, *, only: str | None = None) -> BenchReport
```

### 确定性纪律
- **导出物建议性词根逐字校验**：`建议` / `可能` / `风险提示` / `注意` / `应` / `考虑` 等词根**不得出现在导出物**（负向词表测试）。
- **真值与引擎共用同一处判定规则定义**，禁止手写第二口径（真值库只存"输入与期望"，**观测由观测器运行时实算**——真值库里出现 `observed` 一类字段即红）。
- 合成数据纪律（`data/README.md` 第三节）：假姓名白名单 + 假机构名；**真实机构/人名/报告一律禁用**。
- 基准**不假装覆盖**：某类用例未生成时 `notes` 如实写"该形态未生成"，并配 `--only` 白名单；"整套件数据缺失"与"跑了没过"**同码不同义、文本可区分**。

### 测试点
| 用例 | 断言 |
|---|---|
| 导出无建议词根 | 遍历导出物，命中禁用词根 → 红（变异验证：塞一个"建议"必红） |
| 导出数值正确 | 变化幅度与真值逐条一致（含 +0% 与负向变化） |
| 真值库无 observed | 扫描真值库字段名，出现 `observed` 即红 |
| 基准达标 + 探活 | 基准全绿；**注入一个已知缺陷 → 基准必须报未达标**（可证伪探活） |
| 未覆盖形态如实标注 | 缺某形态 → `notes` 明示 + `not_enabled` 与"未达标"文本可区分 |

## 跨模块：门禁与基建（M0 落地）

| 基建件 | 位置 | 出口门 |
|---|---|---|
| PII gate 阳性+阴性双向测试 | `tests/test_pii_gate.py` | 真实报告形态**被拦**；假数据白名单**放行** |
| README 安装面五面对账 | `tests/test_readme_gate.py` | 五面全绿；变异验证 ×5 全红后恢复绿 |
| 编码守卫（cp1252 复现） | `tests/test_encoding.py` | 窄编码流下不 `UnicodeEncodeError` |
| 行尾 CR 守门 | `tests/test_line_endings.py` | 已跟踪文本文件零 `\r` |
| 双跑字节一致 | `tests/test_determinism.py` | 同输入两次产物 sha256 相同 |
| 退出码契约 | `tests/test_exit_codes.py` | 0/1/2/3/4 各至少一条断言 |
| 桩哨兵串扫描 | `tests/test_no_stub_sentinels.py` | `src/`+`tools/` 零 `NotImplementedError`/`placeholder`/空 `pass` 测试 |

**"桩"三种形态都不让门变红，故必须专设一条扫描**（sprint M6 实录教训）：① 空 `pass` 测试（收集成功、`exit 0`）；② `NotImplementedError` 桩函数；③ manifest 里 `"sha256": "placeholder"`。M0 即建守门，避免潜伏一个里程碑。

**每条新增/改写的守门都要做一次变异验证**：故意弄坏被测行为 → 门必须变红；弄坏后仍绿 = 假门（尤其 `assert "xxx" in source` 这类字面断言证明不了"函数被调用"）。判别口诀：**"我删掉这段逻辑，测试会红吗？"**
