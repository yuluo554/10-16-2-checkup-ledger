# 02 · 架构与技术选型 — CheckupLedger（体检台账工作台）

- 上游依据：`plan/01-题目文档.md`（十段式定稿）
- 数值口径唯一来源：`data/README.md` 第五节「数值口径纪律」（本文档与代码注记一律引用，不重写口径）
- 状态：v1 2026-10-16（M0 定稿）

## 一、交付形态定案

| 项 | 定案 | 理由 |
|---|---|---|
| 主形态 | **CLI + 本地单文件 HTML 报告** | 纯本地零上传最易证伪（产物内无出站栈可静态断言）；免安装交付物可单文件分发 |
| 次要形态 | PySide6 桌面（**留扩展，首期不做**） | 首期强绑桌面打包会把打包变量带进每个里程碑；CLI 内核 + 渲染层分离后，桌面只是另一个消费端 |
| 数据落地 | 本地 SQLite 台账（`*.db` 入 .gitignore） | 纵向持久状态是本题独特性所在（非通用 LLM 能力） |
| 分发形态 | ① 源码包（`pip install` 或裸 clone）② 免安装冻结产物（PyInstaller，M5） | 两条通路都要过"安装面对账"（见第五节） |
| 网络行为 | **零出站**：无 telemetry、无云端 API、无更新检查 | 隐私红线；冻结产物内无 TLS 组件可扫产物断言 |

## 二、分层架构与统一中间表示

```
                      ┌────────────────────────────────────────────┐
  PDF / 扫描图  ──►   │ ① 输入层 ingest   文本层直读 / RapidOCR    │
                      │    产出：RawLine[]（原文+页码+置信度）      │
                      └────────────────────┬───────────────────────┘
                                           │ 低置信行 ⛔ 强制人工复核（未复核不向下）
                      ┌────────────────────▼───────────────────────┐
                      │ ② 规范化层 normalize   指标名字典 + 单位归一 │
                      │    产出：Measurement[]（canonical/值/单位）  │
                      │    未映射 → 待人工映射队列（不猜不编）        │
                      └────────────────────┬───────────────────────┘
                      ┌────────────────────▼───────────────────────┐
                      │ ③ 区间判定层 judge   三级优先 + 四态标记     │
                      │    产出：Judged[]（H/L/normal/not_assessed） │
                      │    纯函数、无 I/O、不做解读                  │
                      └────────────────────┬───────────────────────┘
                      ┌────────────────────▼───────────────────────┐
                      │ ④ 台账层 ledger   SQLite（人/指标/日期）     │
                      └────┬──────────────────────────┬────────────┘
                           │                          │
              ┌────────────▼──────────┐   ┌───────────▼────────────────┐
              │ ⑤a 就诊摘要导出 export │   │ ⑤b 本地 HTML 报告 report    │
              │  CSV / Markdown        │   │  折线+区间带+自身历史分位     │
              │  只陈述事实数值与幅度    │   │  零外链、渲染层零判定         │
              └───────────────────────┘   └────────────────────────────┘
```

**统一中间表示（IR）**：全链路只有四个 dataclass（`src/checkup_ledger/model.py`），两侧输入都归约到它，比对问题因此变成结构化对齐。

| IR 类型 | 字段（定稿） | 产出层 |
|---|---|---|
| `RawLine` | `page` / `line_no` / `text` / `confidence` / `source_file` | ① |
| `Measurement` | `canonical_name` / `raw_name` / `value` / `unit` / `raw_unit` / `ref_range_printed`（报告自印区间，可空）/ `line_ref`（指回 RawLine）/ `reviewed` | ② |
| `Judged` | `measurement` / `flag`（`high`/`low`/`normal`/`not_assessed`）/ `range_used` / `range_source`（`report_printed`/`builtin_default`/`none`） | ③ |
| `TrendPoint` | `canonical_name` / `date` / `value` / `delta` / `delta_pct`（相对上一可比值）/ `direction`（三态事实归类，由 `engine.trend_direction` 实算） | ④/⑤a/⑤b |

**分层纪律（静态门禁守）**：① 输入层**只做抽取、不做数值语义判断**（不 import 判定内核、不产出判定态；行装配模块是纯几何/文本逻辑，无 I/O import）；② 规范化层的 `mapping.py`/`parse.py` 是**纯函数**（不 import 文件 I/O、不读时钟；别名表与单位表经参数接收），**只做映射、不做判定**（不 import 判定内核、不产出判定态）——文件读取唯一落在编排层 `pipeline.py`；③ 判定层是纯函数模块，**不 import 文件 I/O、不读配置、不联网**；④ 台账层只**消费** `Judged`（不 import 判定函数 `compare`/`judge`、不产出判定态；允许 import 趋势函数——趋势三态是"事实归类"，须单点实算）；⑤a 导出层与 ⑤b 渲染层**只陈述事实、不重算判定**，两层的**建议词根门**都是出口常驻断言。

**M4 新增的"计算 / 装配分离"**：渲染要画折线**必须**做算术（坐标换算）与比较（求值域上下界）——把这两件事挤进装配模块，就只能靠"别再写比较"这句口头纪律守，而它守不住（坐标换算本身就需要比较）。故按**语义**划线：算术与比较只准落在 `report/chart.py`（**看不到判定态**、不做"值 vs 区间"的比较、不 import 判定内核），`report/html.py` 与 `report/trend.py` 只剩拼接（AST 断言：无算术、无大小比较、不 import 引擎）。

```

src/checkup_ledger/         运行时代码（随包安装）
  data/                     随包数据白名单：内置区间知识库 YAML + 阈值配置（运行时必需）
  cli.py                    命令行入口 + 退出码契约

  normalize/                模块② 规范化层（mapping/parse 纯函数 + pipeline 编排）
  engine/compare.py         判定内核（四态边界比较 + 趋势三态，纯函数）
  ledger/                   模块④ 纵向台账（schema/errors + __init__ 三入口，M4）
  export/                   模块⑤a 导出（CSV/MD，建议词根门，M4）
  report/                   模块⑤b 渲染（chart 图元计算 / trend 装配 / html 拼接 / guard 零外链，M4）
tests/                      门禁与基准测试

```

**为什么内置区间知识库放包内 `src/checkup_ledger/data/`**：它是**运行时必需**的随包数据（"交付物内可达全部承诺能力"的承重件），必须随 `pip install` 进入安装面；`data/` 顶层目录是**开发期资产**（合成样例、查证记录），不随包。两者语义不同，混放会让"随包白名单"与"仓库台账"的边界失守。

## 四、技术与依赖选型

| 用途 | 选型 | 版本 | 为何不是别的 |
|---|---|---|---|
| 语言底线 | Python **3.8** | — | 本机双通道 3.8.8 / 3.12.10 实测在列；3.8 是最严约束通道，跨版本差异由 CI 矩阵兜 |
| 判定/台账/导出/渲染 | **纯标准库** | — | `sqlite3` / `csv` / `json` / 字面量 HTML 模板；判定内核零依赖才谈得上"确定性可复现" |
| 内置区间知识库 | **YAML + PyYAML** | `>=6.0` | 题目与双先例（LabLens/bloodio）均以人可读 YAML 承载"逐条挂来源"；自写 YAML 子集解析器是造轮子且易错 |
| PDF 文本层直读 | `pdfplumber` | `>=0.11` | MIT 许可；纯 Python 无编译依赖，冻结打包友好。（PyMuPDF 为 AGPL，许可面更紧） |
| 扫描件 OCR | `rapidocr-onnxruntime` | `>=1.3` | ONNX Runtime CPU 本地推理、零联网；中文印刷表格主力场景（题目已核 8148★） |
| 测试 | `pytest` | `>=7` | 与 CI 矩阵同集合 |
| 冻结打包 | `pyinstaller` | `>=6.0` | 仅 CLI 目标可用 `>=5.13,<6`；本项目 M5 若同时打桌面则强制 `>=6` —— 固定在装了 ≥6 的那条解释器通道 |

**关键决策：首期不引任何 LLM / 任何网络客户端库。** 判定 100% 确定性代码（题目第三节红线）；差异化的正是"确定性 vs 大模型解读"。

## 五、依赖分层与安装面（extras 对账）

| extras | 内容 | 用途 |
|---|---|---|
| （核心 `dependencies`） | `PyYAML>=6.0` | 区间知识库解析——**核心能力，不做可选** |
| `[dev]` | `pytest>=7` | 测试 |
| `[pdf]` | `pdfplumber>=0.11` | 文本层直读（M2） |
| `[ocr]` | `rapidocr-onnxruntime>=1.3` | 扫描件兜底（M2） |
| `[freeze]` | `pyinstaller>=6.0` | 冻结构建（M5） |

**安装面对账五面**（`tests/test_readme_gate.py` 一个文件锁死，M0 建立，随交付形态扩张）：

1. README 命令/旗标 → CLI `build_parser()` 反射（逐行关联旗标到子命令，防张冠李戴）
2. CLI 子命令 → README 反向覆盖（防"实现了没写文档"/"写了文档没实现"）
3. `tests/` 全部 import（AST 从严收集，**含函数体内 import**）→ 落点四分法（stdlib 冻结名单 / extras / 本包 / tools 注入）
4. README 的 `pip install -e ".[...]"` 行 ↔ `pyproject.toml` 声明的 extras 双向一致
5. `packages.find` include → 真实包布局（含子包在位 + 包内数据目录在位）

**配套纪律**：stdlib 名单用**冻结名单制**，不用 `sys.stdlib_module_names`（3.10+ 才有，3.8 上取到空集 → 每个标准库都判成第三方 → 全量假红）。

**三条通路必须分别冒烟**（`sys.path` 来源不同，一种通不等于另一种通）：

| 通路 | 形态 | `sys.path` 来源 |
|---|---|---|
| 源码态 | `python -m checkup_ledger …`（仓库根） | CWD |
| 安装态 | 裸 `checkup-ledger …`（README 快速开始让用户敲的） | 安装记录 |
| 冻结态 | `checkup-ledger.exe …`（M5） | PyInstaller 引导 |

CI 三条都要跑（骨架期前两条），否则"我们的包没进安装面"这类缺陷会静默潜伏。

## 六、退出码契约（M0 锁定，写进 README 与测试）

| 码 | 语义 | 触发例 |
|---|---|---|
| `0` | 成功 / 门禁通过 / 基准达标 | 正常完成；判定检出 H/L **仍为 0**（业务结果不是错误） |
| `1` | 检出问题（门禁或校核**不通过**） | 区间库条目缺来源字段；基准未达标；自检失败；台账库缺库或损坏 |
| `2` | 用法错误 | 未知子命令、未知旗标、缺必需参数、参数值非法（如 `ledger` 入库缺 `--date`） |
| `3` | 缺可选依赖 | 调 `ingest`/`normalize`/`ledger`/`export`/`report` 而未装 `[pdf]`/`[ocr]`（**缺依赖走契约，不裸抛异常**） |

> **`4`（`NOT_READY` 阶段未就绪）已整项退役**（M4）：首期五模块（输入 / 规范化 /
> 判定 / 台账 / 导出+报告）全部落地，拦截名单清空，`EXIT_NOT_READY` 常量与
> `cmd_not_ready` 一并删除。历史轨迹：M2 退役 `ingest` 触发点、M3 退役 `normalize`
> 触发点（两次均保留常量，因其余模块仍在使用它），M4 整项退役。退役走**四处同步**
> （常量 / CLI 分派 / 文档 / 测试含 `not hasattr` 防复活断言），少一处即幽灵语义复活。
> **为什么删掉而不是"留着以后用"**：留一个恒不被触发的码，等于给后来者一个
> "这里还有未就绪语义"的假线索，也让退出码表里的 `4` 永远无法解释。若将来真引入
> 新的未落地模块，届时**重新引入**并在那个里程碑退役它——比留一个死码便宜。

**语义纪律**：
- `1` 专指"工具**查出了不合规**"，语义是**成功执行 + 负面结论**；非零 ≠ 跑挂。
- 未实现模块**不伪造空结果**——`4` 存在期间一律显式拦截，绝不返回"0 条记录"这种谎报。
- 退出码语义**锁进测试**（每码至少一条断言），`--help` 与 README 同步表述。

## 七、确定性纪律（承重件，M0 即落地）

| 纪律 | 落法 | 守门测试 |
|---|---|---|
| 写盘单点 | 所有产物一律经 `serialize.write_atomic()`，**禁止各子命令各写各的 `open()+json.dump()`** | AST 扫描：`json.dump`/`write_text` 只准出现在 serialize 模块 |
| 序列化契约冻结 | `json.dumps(sort_keys=True, ensure_ascii=False, indent=2)` + LF + 结尾换行；`ensure_ascii=False` 是中文项目必选（否则 diff 不可读） | 同输入双跑**逐字节一致**断言 |
| 原子写 | 写临时文件 → `os.replace`，防中断留半个产物 | 临时文件不残留断言 |
| 编码守卫 | 入口 `encoding.ensure_utf8_stdio()`：按 `stream.encoding` 探针决定是否 `reconfigure`（cp936 中文控制台保持不动） | `TextIOWrapper(BytesIO(), encoding="cp1252", errors="strict")` 复现 CI 编码面（本机即可跑） |
| 子进程编码 | 所有 `subprocess` 显式传 `encoding=`/`errors=`（**无环境变量可替代**） | 扫描面断言无裸 `subprocess.run(text=True)` |
| 行尾归一 | `.gitattributes` `* text=auto eol=lf`；冻结快照标 `-text`（防克隆时字节归一化） | CR 守门：扫描已跟踪文本文件无 `\r` |
| 无系统时钟进产物 | 产物内无时间戳字段；需要时用显式参数传入 | 双跑逐字节一致（时间戳会让它红） |
| 自研确定性 RNG | 合成样例生成禁用 stdlib `random`/`set` 迭代序 | `--check` 再生成位级一致（M1 建立） |

**"确定性"的主语要问清**：本项目承诺的是**"我们的处理步骤对同一输入产出相同字节"**（可承诺）；**不承诺**跨机重建的冻结 exe 逐字节一致（PyInstaller 产物含构建期时间戳，M5 留档按"树摘要 + 结构口径"分情形对账）。

## 八、隐私红线与 PII gate（M0 落地）

- **真实体检报告永不入库、永不入 git、永不入示例目录**；台账 `*.db` 入 .gitignore；OCR 模型缓存不入 git。
- `.githooks/pre-commit` 调 `tools/pii_gate.py`，**拦截面**（三重）：
  1. **路径面**：staged 文件落在禁用路径（`real_reports/`、`private/`、`_reports/`）→ 拦
  2. **类型面**：staged 的 `*.pdf`/`*.jpg`/`*.png`/`*.db` **不在样例白名单**（`data/samples/**`）→ 拦
  3. **内容面**：staged 文本里出现真实机构名模式 / 手机号 / 身份证号 / 真实报告页眉特征 → 拦
- 假数据白名单（`data/README.md` 附录）为唯一放行依据；新增白名单条目须登记附录（**白名单是判定词表，扩表是正常维护动作、绕过表是造假**）。
- **自证要求**：PII gate 必须配**阳性样本**（应被拦）与**阴性对照**（假数据白名单内应放行）双向测试——只测一边的门等于没测。
- 首启免责声明（CLI 首次运行读一次标记文件后落 `~/.checkup_ledger/accepted`，**M4 已落地**）+ README 常驻免责（M0 即写）。
  **M4 落地要点**：标记落在**用户主目录**（不是仓库/包内——那是用户级接受状态，落包内等于"装一次=所有人接受过"）；
  **写不进去不算失败**（只读环境下免责照样打印，宁可多念一次不可漏念一次）；
  标记文件**只记"接受过"这一个事实**（不写时间戳/机器名——一个免责标记不该变成指纹）。
  实测抓到的真缺陷：`argv is None`（真实入口 `python -m`/裸 console script 的形态）时初版实现
  `if not argv: return` 把"用户真敲了命令"读成"没有参数"，免责**在真实入口永不打印**——
  而单测显式传 `["ledger", …]` 会通过。已修为回落 `sys.argv[1:]` 并补 `argv=None` 回归测试。
- **台账 `*.db` 落在 `~/.checkup_ledger/ledger.db`**（不是仓库相对路径）：它是个人健康数据，
  落仓库会让 `git status` 就看得见（PII gate 只在提交时拦，那时文件已在工作树里）。
- **测试不得污染真实主目录**（实测抓到的真缺陷）：`ledger`/`export`/`report` 经 `main()`
  会触发首启免责，测试若直接调 `main()`（`helpers.run_cli` 就是）就会把标记写进
  **开发者/CI 机器的真实 `~`**。故 `tests/helpers.py` 导入时把免责标记重定向到仓库外的
  一次性目录，并配两条门（隔离路径 ≠ 默认标记路径 + 跑数据命令后真实主目录不出现
  `.checkup_ledger`）。显式 `env={}` 的单元用例**不受**影响（它们走 `home` 参数）。

## 九、零字面量门禁（M1 建立，M0 预置位置）

判定区间数值**只能来自知识库 YAML**，代码里不得出现第二份真相。M1 在 token 集可枚举后建立：

- **扫描面**：`src/` 全部源码（含 docstring/注释/字符串字面量）+ `tools/` + `tests/` 基准侧；
- **token 集**：内置区间 YAML 的上下限数值（词边界匹配）；豁免口径写死（如 0/1 等结构常数、精度约定）；
- **判别**：门禁红了先问"这个数是规则值还是结构常数"——**防御性常数不是豁免理由**（该删就删）；
- **变异验证**：往引擎里塞一个区间字面量 → 门禁必须变红；弄坏后仍绿 = 假门。

## 十、扩展点（首期不做，接口预留）

| 扩展 | 预留方式 | 不做的理由 |
|---|---|---|
| 多语言 OCR | 输入层引擎按 `engine_id` 注册表分派 | 中文印刷件是主场景，多语言无真值可验 |

| 家庭多成员 | 台账 schema 的 `subject_id` 字段 M0 即留列（默认 `default`） | 多成员管理是 UI/权限问题，非判定内核问题 |

## 十一、技术风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| WS/T 404/405 全文不可直连（题目已实测 412/502） | 内置区间无法逐条对照标准原文 | 已有定案：**来源标注 YAML + 报告自印区间最优先**三级设计（双先例支撑）；每条 entry 的 `source.status` 如实记 `pending`/`verified`，**pending 不进判定路径**，宁拒判不臆造 |
| OCR 低置信行污染数值 | 错值静默入库，比"漏值"危险 | 阈值单点定义（`data/README.md` 口径节第 4 条）；低置信强制人工复核；**未复核行不落库**（门禁测试守） |
| 区间边界开闭语义误用 | 边界值判反（"不超过 40" 的 40 该判正常） | 边界开闭落 YAML 字段，**判定内核单点实现**；基准含 `threshold_exact`（恰在边界）与 `near_miss`（差一点）双向用例 |
| 打包后数据目录解析失败 | 冻结产物"跑起来但找不到知识库" | `paths.py` 三分支（源码/安装/冻结）+ 冻结态自检断言"数据目录落在 exe 目录内" |
| 中文控制台编码 | 用户侧 `UnicodeEncodeError` | 入口 stdio 守卫，探针式 reconfigure（不硬改 cp936） |
