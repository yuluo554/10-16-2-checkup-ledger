## 诚实口径（全程生效，每棒复查）

**未推送 = 未跑 CI。** 本仓库在 M6 之前无远端，所有 CI 类 DoD 一律写：

> **本地等价校验（未接远端，CI 待首推验证）**

并**列出可指认的替代证据**（双解释器全量测试 / 生成器 `--check` / 门禁 selftest / 基准 / 冻结态验收），把**本机不可实跑的通路显式标注"待首推验证"**。"等价"永远有缺口，写清缺口比笼统一句"通过"诚实且可审计。M6 首推后**据实补记**真实 run id（补记是追加事实，不是回填美化；首跑若失败，失败记录保留不抹除）。

同理适用于一切"未实际执行却打勾"的项：gate 只能在真实执行并留下证据后打勾。

  为了讲清"单侧区间"与"读不出"的区别，直接写了具体端点（与 YAML 区间数值撞值）——
  门（正确地）判红。修正方式是把示例一律改成 `<下限>`/`<上限>` 这类**指代**。
  这正是 M1 建门时写明的理由："抄进注释的端点同样让改 YAML 改不动它"。
- **单位只做全局匹配会张冠李戴**（实测补门）：首版 `match_unit` 只看单位表（全局），
  于是 ALT 配 `mmol/L` 会被照常判定——单位"认得"但量纲不属于该指标。
  已加 `unit_belongs_to` 门并配变异验证。
- **"没写单位"与"认不出单位"合并成一个原因码是错的**：两者处置方向不同
  （核对报告排版 vs 扩单位表），已拆成 `unit_absent` / `unit_unmapped`。
- **"数值+单位粘住"的写法会误报原因码**：`<数值><单位>` 整段解析失败会报
  `value_unlocated`，人工按"数值没读到"去找就错了方向。已加拆解逻辑。
- **自印区间开闭是口径属性、不是报告事实**（如实登记的局限）：报告只印端点、不印开闭，
  故自印区间沿用该指标的内置口径。若某报告实际用开区间而内置口径是闭区间，
  边界值判定会与报告意图不符。首期接受此局限，登记于 `data/README.md` 第八节。

**M4 期间修掉的真缺陷**（留档，防重犯）：

1. **首启免责在真实入口永不触发**：`main()` 从 `python -m`/裸 console script 进来时

   "没有参数"。而单测显式传 `["ledger", …]` 会通过，**缺陷只在真实通路暴露**

2. **单点序列给出"100% 分位"**：算术上成立，但会让人读成"处在历史最高位"——

4. **日期形状不校验零填充**：`2024-3-11` 与 `2024-03-11` 字符串不等但语义相同，

5. **`mark_accepted` 只接 `OSError`**：路径含非法字符时 `os.makedirs` 抛

6. **台账"覆盖计数"漏算 `source_file`**：只按 (指标, 日期) 查，把"新插入"报成

**M5 实测偏差与真缺陷**（留档，防重犯）：

1. **`ssl`/`socket` 不是"排掉就好"**：`--exclude-module socket` 会让 `import pdfplumber`
   直接 `ModuleNotFoundError`（成因：`pdfminer/__init__.py` 模块级 `from importlib.metadata
   import version` → `importlib.metadata` 模块级 `import email` → `email.utils` 模块级
   `import socket`）。实测 `ingest` 报 exit 3"缺 pdfplumber，底层错误 No module named
   'socket'"。**处置**：排除全部具备出站能力的组件（TLS/HTTP/FTP/SMTP/telnet/异步与并发），
   保留 `socket`/`selectors` 这两个**不含协议栈**的名字，并把这笔残留**显式登记**
   （`SOCKET_RESIDUE_MODULES` + 理由 + 由测试锁死清单）——不静默放过，也不为了凑
   "包里没有 socket"而让产物跑不起来。
2. **只扫 dist 目录树的门对 PYZ 内的模块是瞎的**：PyInstaller 6 的 onedir 把纯 Python
   模块打进 exe 内的 PYZ 归档，**目录里没有对应文件**。实测只扫目录时 `ssl` 完全不可见
   ——故必须用 `CArchiveReader` 读模块名表（这条同时写进"为什么"注释）。
3. **冻结产物不吃 `PYTHONUTF8` / `PYTHONIOENCODING`**：两者都是 CPython 启动配置项，
   PyInstaller 引导程序自己构造 `PyConfig` 并覆盖（实测三组环境变量下输出字节完全相同）。
   产物于是**按控制台编码自适应**——这是正确行为（中文控制台不该被硬改），要改的是
   验证侧的读取方式：`decode_output()` 先严格试 utf-8、失败回落 locale 编码。
   初版验证侧硬编码 utf-8，把 `bench` 的"达标"读成乱码 → 断言假红（实测踩到）。
4. **同机连打两次的 exe sha256 都不同**（`8d35d50b…` vs `59ae0d15…`，体积同为
   2,872,954 字节）：PyInstaller 产物含构建期时间戳。故"确定性"只承诺**同一份 dist
   的打包过程**，exe 本体逐字节可复现这条**不成立**（原计划只写"不承诺跨机一致"，
   实测更严：跨次也不成立，如实收窄口径）。
5. **`package-data` 里有一个空模式**（`data/*.yml`，仓库当前只有 `.yaml`）：初版白名单
   展开逻辑对"模式匹配不到文件"直接报错，构建因此起不来。处置：保留该模式（将来新增
   `.yml` 分册不必改安装面），但把"合法的空模式"改为**逐条登记理由**（
   `DECLARED_EMPTY_PATTERNS` + 测试锁死清单）——与零字面量门禁的 `EXEMPT_FILES`
   同一套纪律；未登记的空模式仍然报错（配变异验证）。
6. **中立环境跑产物会在 CWD 里臆造一个 `~` 目录**（真缺陷，用户可见的污染）：
   `env -i` 等价环境里没有 `USERPROFILE`/`HOMEDRIVE`+`HOMEPATH`，
   `os.path.expanduser("~")` **原样返回 `~`**，经 `abspath` 落成"CWD 下的 `~` 文件夹"。
   实测：在中立目录跑 `ledger`（触发首启免责）后，工作目录里真的多出
   `~/.checkup_ledger/accepted`。处置与"写不进去不算失败"同向：解不出主目录 =
   **没有可写的标记位置 → 不写**，按未接受处理（免责照念），**绝不回落 CWD**；
   并补三条回归测试（无主目录不建目录 / 主目录可解析时照旧落盘（配对守）/
   显式传未展开的 `~` 也按解不出处理）+ 一条端到端冻结态门（真产物中立环境跑
   `ledger` 后 CWD 不出现 `~`）+ 2 条变异验证。
7. **两处门是"镜子"（拿实现当规格）**：初版"构建排除了全部出站组件"与"白名单每份都
   拷了"两条断言都**从被测常量取期望**——把 `ssl` 从常量里删掉、构建跟着少排一项，
   断言仍会通过。处置：把判据面**钉死在测试侧**（`REQUIRED_OUTBOUND_COMPONENTS` /
   `REQUIRED_PACKAGED_DATA`），再断言实现**覆盖**它（实现多排几项算更严，不算违规），
   并各配变异验证。

## 风险与偏差处置

| 风险 | 处置 |
|---|---|
| M1 区间条目录入耗时超预期 | **优先级不变**：宁可少录条目、`status: pending`，也不降"逐条挂来源"的纪律——降级会污染判定路径 |
| CI 首跑暴露环境差异 | 预留诊断轮；**环境差异型失败不算"动内核"**，修 CI 配置与测试环境依赖不违反冻结纪律 |
| OCR 权重下载失败（国内网络） | hf-mirror / ModelScope 通道；失败则 M2 如实记偏差并保留 `[ocr]` 为"依赖可装但权重待下载"。**M2 实测：该风险在 `rapidocr-onnxruntime` 1.3.x 上不成立**——ONNX 权重**随 wheel 内嵌**（det/rec/cls 三个 `.onnx` 共约 15MB），`pip install` 即完成，无需另下。如实回写（风险项保留但标注"实测未发生"） |
| 冻结产物体积过大 | `excludes` 按目标分档（CLI 目标排除 Qt 系）；M5 **实测记录体积对比**：不排除任何模块的朴素构建 **60 MB**、PyZ 模块 480 个；加排除后 **44 MB**、269 个（Qt 系 + 图像/数值重件 + 出站组件）。**实测：本机从未把 PySide6 拉进包**（无模块级引用），故 `excludes` 是**防御性口径**而非体积主因——体积主因是 `pdfminer`→`cryptography`（OpenSSL 运行时 `libcrypto-3.dll`）这条 PDF 文本层的真实依赖链 |
